# CSS Allowlist — info.skygorilla.hr

**Status:** CANONICAL GOVERNANCE RULE
**Packet authority:** `INFO_SKYGORILLA_CSS_ALLOWLIST_M1`
**Date:** 2026-06-04
**Hard rule:** CSS is allowed here because independence is more important than live DS coupling.

---

## Rule summary

`info.skygorilla.hr` is a static resilience surface. It is allowed to own committed static CSS.

This CSS is **not drift** if it is:

- local fallback CSS (`styles.css`)
- vendored Blade fallback snapshot CSS (`vendor/blade-fallback/*.css`)
- generated by the approved Blade fallback exporter (`packages/blade-fallback-exporter`)
- pinned by `vendor/blade-fallback/manifest.json`
- committed intentionally
- **not** imported from the live monorepo at runtime

**For normal app surfaces, CSS must obey DS/source ownership.**
**For `info.skygorilla.hr`, static CSS is part of the resilience architecture.**

---

## Allowed CSS locations

```txt
styles.css                           → FALLBACK_SOURCE_CSS
vendor/blade-fallback/tokens.css     → APPROVED_VENDOR_STATIC_CSS
vendor/blade-fallback/components.css → APPROVED_VENDOR_STATIC_CSS
vendor/blade-fallback/fallback.css   → APPROVED_VENDOR_STATIC_CSS
```

## Allowed CSS sources

```txt
manual fallback CSS (standalone, no imports)
approved static CSS copied from Blade fallback exporter output
approved generated CSS snapshot from packages/blade-fallback-exporter
```

## Required provenance manifest

`vendor/blade-fallback/manifest.json` is **required** and must contain:

```json
{
  "kit": "blade-fallback",
  "version": "0.1.0",
  "source": "@skygorilla/blade",
  "mode": "static-export",
  "runtimeDependency": false,
  "approvedFor": "info.skygorilla.hr",
  "exportDate": "YYYY-MM-DD",
  "sourceCommit": "UNKNOWN_OR_HASH",
  "contains": ["tokens", "cards", "buttons", "status-banner", "metric-card"]
}
```

## Forbidden actions

```txt
Do not delete fallback CSS as drift.
Do not replace local CSS with live Blade imports.
Do not import @skygorilla/blade at runtime.
Do not require monorepo install/build for fallback runtime.
Do not require Storybook to render fallback.
Do not classify vendored fallback CSS as generated-output contamination.
```

---

## Removal rule

Any removal or replacement of fallback CSS requires an approved packet:

```txt
INFO_SKYGORILLA_CSS_SNAPSHOT_REPLACEMENT_M1
```

### Replacement flow

```txt
1. Run packages/blade-fallback-exporter.
2. Generate new static CSS kit into dist/fallback-kit/.
3. Compare visual/regression against current vendor/blade-fallback/.
4. Update manifest.json (version, exportDate, sourceCommit).
5. Commit snapshot into skygorilla-info-fallback/vendor/blade-fallback/.
6. Verify Cloudflare Pages preview (https://skygorilla-info-fallback.pages.dev).
7. Verify https://info.skygorilla.hr after propagation.
8. Only then replace old CSS.
```

---

## Hard resilience rule

```txt
The fallback must run if Blade, Nakovan, Storybook, npm workspaces,
Firebase, Firestore, or Supabase are broken.

Therefore:
  - The fallback MAY use Blade-inspired static CSS (vendored snapshot).
  - The fallback MUST NOT depend on Blade runtime.
  - The fallback MUST NOT depend on any workspace npm install.
  - The fallback MUST NOT depend on any build step to render.
```
